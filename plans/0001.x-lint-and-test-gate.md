## 1. Problem Statement & Context

Plan 0001 shipped 34 PHP files and self-reported 🟡 Partial verification. § 5.2 named exactly two
commands that never ran, and § 5.3 recorded the consequence:

- `composer lint` (phpcs) — "not installed".
- `composer test` (phpunit) — "not installed, and additionally needs `WP_TESTS_DIR` plus a MySQL test database".

So three separate claims are currently unbacked:

1. **The code is PHPCS-clean.** `phpcs.xml.dist` configures the `WordPress` ruleset, `PHPCompatibilityWP`
   with `testVersion 7.4-`, the `WordPress.WP.I18n` text domain `speedy-sensor`, and `PrefixAllGlobals`.
   Nobody has ever executed it. Violations are likely.
2. **The code is PHP 7.4-compatible.** `composer.json` declares `"php": ">=7.4"`. The only interpreter
   on this machine is PHP 8.5.10, so `php -l` passing proves nothing about the declared floor — PHP 8.0+
   syntax such as named arguments, `match`, `str_contains`, promoted constructor properties or nullsafe
   operators would sail through. `PHPCompatibilityWP` is the configured detector and is unrun. This is the
   single highest-risk unverified claim in the repo, because the floor is a published promise.
3. **The three test suites pass.** `tests/SettingsTest.php`, `tests/AttributionTest.php` and
   `tests/WebVitalsTest.php` extend `WP_UnitTestCase`. They have never executed once.

Meanwhile `plans/README.md` carries the gate as 🔴 CLOSED, and the plugin is admin-only, never
installed against a real WordPress, and unproven end to end.

## 3. Architecture & Design

```
        verification checkpoint (this plan)
                     │
   ┌─────────────────┼──────────────────────────┐
   │                 │                          │
   ▼                 ▼                          ▼
Composer        composer lint            composer test
(no sudo,   →  phpcs: WordPress +   →  phpunit + WP_UnitTestCase
 user-local)    PHPCompatibilityWP        │
   │                 │                  needs WP_TESTS_DIR
   │                 │                  + MySQL + mysqli
   ▼                 ▼                          │
 vendor/         fix every                     ▼
 (gitignored)    violation               🔴 BLOCKED on this
 (never shipped) in source              machine: no mysqli,
                                         no MySQL server
```

Decision: install Composer to `~/.local/bin` rather than a system path. `~/.local/bin` is already on
`PATH`, so `composer` resolves with no shell changes and no `sudo`. Composer is dev-only; `.gitignore`
excludes `vendor/` and `.gitattributes` `export-ignore`s `/composer.json`, so neither the binary nor
its output can reach a distributed build. The runtime autoloader is `includes/autoload.php` and does
not consult `vendor/`.

Decision: treat a PHPCS violation as a code defect to fix, not as a rule to relax. Plan 0001's code
has never been linted, so a non-zero violation count is the expected and legitimate outcome of this
checkpoint. Each fix is a separate small commit-worthy edit, kept to the reported line, matching
surrounding style.

Decision: `PHPCompatibilityWP` findings are treated as release-blocking, not cosmetic. The runtime
floor in `composer.json` is a promise to hosts; a PHP 8-only construct in shipped code is a real bug
for every host on 7.4, regardless of what 8.5 reports.

Decision: if `composer test` cannot run, record the exact failing command and its output in § 5.3,
state the three missing prerequisites individually, and leave the gate 🔴 OPEN. Do **not** mark the
test suites as passing, and do **not** substitute `php -l` for a test run.

### 7.1 Shipped

1. **Composer toolchain installed** without `sudo`, SHA-384 signature verified against
   `composer.github.io/installer.sig`, at `~/.local/bin/composer` (2.10.3).
2. **All 305 lint violations cleared.** `composer lint` now exits 0:
   - 120 auto-fixed by the repo's own `composer lint:fix` (array alignment, end-of-file newlines,
     double quotes, docblock spacing).
   - 97 SQL findings (`PreparedSQL.NotPrepared` ×80, `InterpolatedNotPrepared` ×9 plus follow-ons)
     resolved with **scoped, justified** inline disables after verifying every one of the 35
     distinct call sites is genuinely `prepare()`-wrapped. WPCS cannot follow the
     `$wpdb->prepare( $var )` indirection, so these are false positives, not bugs.
   - 30 `EscapeOutput` findings on `echo View::tile( … )` resolved with justified inline disables
     after reading `View::tile()` and confirming it `esc_html`s every argument and `esc_attr`s the
     tone.
   - 4 unused parameters resolved using the idiom already present in `Pages\Database`: `unset( $settings )`.
   - 2 nonce findings on read-only screen identifiers, and 2 `CronInterval` findings whose interval is
     computed from settings, annotated with the reason they cannot be satisfied structurally.
   - `phpcs.xml.dist` gained four narrowly scoped `exclude-pattern` rules. Each is a genuine
     conflict, not a papering-over: PascalCase PSR-4 class files vs a hyphenated-lowercase filename
     sniff, and WordPress-runtime sniffs applied to `bin/` and `tests/`, which are `export-ignore`d
     and never load inside WordPress.

### 7.2 Deviations from the plan

1. **`composer test` was not made to pass, and was not attempted further than diagnosis.** The plan
   expected it to run. It cannot: no `mysqli`, no MySQL server, no test library, and all three need
   `sudo`. Per § 3 Step 3.4 the gate was left **OPEN** rather than worked around. No test was skipped,
   weakened or marked as passing.
2. **A severity-3 downgrade of `WordPress.DB.PreparedSQL` was tried and reverted.** It cleared all
   80 errors in one edit, but it would also silence genuinely unprepared queries written in future,
   which `AGENTS.md` forbids ("Never weaken tests, linters, or CI to make things pass"). Verified by
   experiment, then reverted in favour of inline disables.
3. **`customAutoEscapedFunctions` was tried and reverted.** Registering `tile`/`sparkline` as
   auto-escaping functions does not work for static method calls in WPCS 3.4 — the sniff reports the
   *class* token (`View`), and neither `customEscapingFunctions` nor `customAutoEscapedFunctions`
   matches it. Verified with a minimal reproduction, then reverted to inline disables.
4. **Composer is a user-local binary, not a system install.** The plan said no `sudo`; this is how
   that was honoured. Consequence: `composer` resolves on `PATH` for this user only.
5. **`tests/` was given a `NonceVerification` exclusion and a filename exclusion** alongside the
   `bin/` ones. Not anticipated, but the same reasoning applies.

### 7.3 Bugs Found and Fixed During Verification

1. **`WebVitalsService::refresh()` accepted a `$route` parameter it never used.** `series()` and
   `latest()` both accept and forward a route, so the signature promised per-route filtering that
   `refresh()` does not perform — a caller could reasonably believe rows were being scoped. All three
   call sites pass no route. The parameter is removed. Note this narrows a public method signature;
   all in-repo callers already pass nothing, and `tests/WebVitalsTest.php:145` calls `refresh()`
   with no arguments, so nothing breaks.
2. **`Settings::is_allowed_api_host()` mixed `||` and `&&` without parentheses.** The intent was
   `host === root || (subdomain check)`. `&&` binds tighter than `||`, so the behaviour was already
   correct, but the expression was ambiguous to read on a security-relevant check. Extracted to
   `$is_subdomain`. **No behaviour change** — verified by reading the operator precedence.

Everything else in the 36-file diff is whitespace, comments, or `unset()` no-ops, verified as such
by diffing every SQL string against `HEAD` (all byte-identical).
